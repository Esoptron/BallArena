# Разработка BallArena

Проект использует Godot **4.7.2 Standard**, GDScript и Compatibility renderer.
Точка запуска — `scenes/launcher.tscn`, запуск всего проекта — F5.

## Структура

- `characters/`: ресурсы персонажей и способностей, единственный источник баланса.
- `scripts/combat/`: независимые от меню контракты, каталог, директор, метрики и проверка состава.
- `scripts/actor/`: общая инфраструктура состояния персонажа.
- `scripts/ui/`: представление, стили и подготовка предпросмотров без боевой логики.
- `scripts/effects/`: общие инструменты геометрии эффектов; основные службы эффектов пока остаются в `scripts/` ради совместимости путей.
- `scenes/` и `levels/`: сцены и данные уровней.
- `tests/`: исполняемые интеграционные проверки; `tests/tooling/` — проверки инструментов на Python; `tests/manual/` — ручные диагностические сцены-скрипты.
- `builds/`: игнорируемые результаты проверок, снимки и сборки. Исходники сюда не помещать.
- `docs/`: описания механик и исторические отчёты. Их цифры не заменяют действующие `.tres`.

Не перемещайте все файлы ради дерева каталогов: существующие сцены, UID и сохранённые ссылки должны продолжать работать. Общие вспомогательные компоненты отделяются по ответственности; небольшие публичные обёртки сохраняют совместимость.

## Изменения и коммиты

Работайте в согласованной с владельцем ветке и папке. Сначала проверяйте Git status и локальные инструкции. Законченное логическое изменение с успешными проверками фиксируйте отдельным коммитом; не накапливайте независимые этапы до конца большой задачи. Публикуйте в согласованный remote/branch. Не включайте кэши, APK, ключи, секреты и локальные файлы инструкции в коммиты.

Для рефакторинга отдельно проверяйте сохранение параметров, порядка событий, расходования боевого RNG, позиций/скоростей, геометрии и слоёв отрисовки. Исправление архитектуры не является разрешением менять баланс или дизайн. Записывайте оставшиеся ограничения проверок, не объявляйте smoke-тест доказательством равного баланса всех героев.

## Контракты кода

- Подписки и регистрации должны быть идемпотентными. Для долгоживущих ссылок на Nodes учитывайте выход из дерева и освобождение; сравнение освобождённого объекта с `null` само по себе не доказывает завершение активного состояния.
- После `await` проверяйте заново объекты, которыми собираетесь пользоваться. Асинхронная работа должна отменяться при смене сцены, освобождать временные ресурсы и снимать busy-флаг на каждом пути выхода.
- Боевые изменения проводят `CombatAbility`/`CombatDirector` через общие damage/heal/status API. Директор не должен читать частные поля конкретного оружия. Случайность эффектов не должна расходовать RNG боя.
- Изменяемые ресурсы/словари параметров и снимки метрик не должны делить вложенные контейнеры с шаблонами. Проверяйте входные профили и состав до частичного изменения бойца.
- UI-метаданные находятся в `scripts/ui/character_text.gd`. Не загружайте целый экран ради словаря имён. Повторяемая настройка портретов находится в `portrait_preview.gd`.
- Статичную геометрию, текст и layout обновляйте по изменению состояния. Косметические массивы и MultiMesh имеют явные бюджеты; увеличение бюджета должно согласовывать буфер. Не возвращайте GPU readback при смерти или плотную равномерную выборку траектории оружия.
- Используйте `.editorconfig` и `.gitattributes`: UTF-8, LF, табы в GDScript. В новых/изменяемых функциях предпочитайте явные имена, типы границ API и обычные многострочные условия. Комментарий объясняет причину ограничения, а не пересказывает строку кода.
- Не маскируйте неожиданные ошибки общим отключением сообщений Godot. В отрицательных тестах допустимо временно подавить ожидаемую диагностическую ошибку с немедленным восстановлением настройки.

## Проверки

Нужны Python **3.10+** без сторонних пакетов и исполняемый файл Godot. Передайте `--godot`, задайте `GODOT_BIN` либо добавьте `godot`/`godot4` в PATH.

```powershell
python -m unittest discover -s tests/tooling -v
python tools/run_tests.py --godot 'C:\path\Godot.exe' --suite headless --jobs 2
python tools/run_tests.py --godot 'C:\path\Godot.exe' --suite graphics
python tools/run_tests.py --list --suite all
```

Для отдельного теста: `--test actor_lifecycle_test`; `--timeout 120` ограничивает каждый процесс. По умолчанию runner сначала импортирует проект. `--skip-import` применим только к уже импортированной копии. Логи, графические снимки и `results.json` находятся в `builds/qa`.

Результат считается успешным только при exit code 0, наличии PASS и отсутствии ошибок/FAIL/утечек. Кадровый лимит без завершённого теста — ошибка. Старый лог очищается перед процессом. Параллельны только отдельные headless-процессы; графические тесты идут последовательно. GPU-распад смерти не запускается в headless: он отдельно проверяется на каждом вооружённом герое.

GitHub Actions проверяет импорт и headless-серию на каждом push в main/PR. Движок закреплён на 4.7.2 и официальной SHA-512, Actions — на commit SHA. Локальная графическая проверка всё равно нужна для изменений рендера/меню. CI на Linux и локальная проверка Windows не заменяют профилирование на телефоне.

## Сборка Android

Только по отдельному запросу владельца:

```powershell
.\tools\build_android.ps1 -GodotPath 'C:\path\Godot.exe'
```

Этот скрипт создаёт APK. Ревью/CI сами его не вызывают. Импорт и экспорт проверяются отдельно, их журналы находятся в `builds/android`. SDK и подпись остаются локальными; подробности — в `docs/android-testing.md`.
