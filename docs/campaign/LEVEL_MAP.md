# Визуальная карта кампании

Отдельная **художественная проба трёх узлов** доступна кнопкой «Новый вид»: [ресурсы, запуск и ограничения качества](MAP_ART_STUDY.md). Описанная ниже карта из двадцати позиций сохраняет своё оформление; новый стиль на неё не переносится до подтверждения.

Карта открывается через **Выбор режима → Основная кампания**. Это один горизонтальный экран: пять существующих уровней, пятнадцать недоступных позиций и туман с табличкой «Скоро выйдет». Стрелки, перетаскивание мышью, колесо и свайп перемещают общий маршрут. HUD и нижняя навигация остаются неподвижными. Возврат из казармы, магазина и бестиария сохраняет положение карты; открытие следующего уровня переводит фокус к нему.

## Файлы

| Файл | Ответственность |
|---|---|
| `scenes/campaign/level_map.tscn` | Самостоятельная сцена экрана |
| `scenes/campaign/level_node.tscn` | Повторно используемая кнопка уровня: номер, BossSlot, ChestSlot, статус, Markers |
| `scripts/campaign/data/level_map.json` | Позиции, состояния, сундуки, зоны, палитра, параллакс, параметры прокрутки |
| `scripts/campaign/map/data.gd` | Проекция сохранённого прогресса на конфигурацию карты; без изменения аккаунта |
| `scripts/campaign/map/screen.gd` | Сборка трёх слоёв, HUD, навигация, масштабирование |
| `scripts/campaign/map/level_node.gd`, `chest.gd` | Внешний вид уровня и сундука, слоты будущих текстур |
| `scripts/campaign/map/scroller.gd` | Ограничения, инерция, плавные стрелки, мышь/тач; защита от запуска уровня после свайпа |
| `scripts/campaign/map/parallax.gd` | Перемещение слоёв с разными коэффициентами |
| `scripts/campaign/map/decor.gd`, `route.gd`, `fog.gd` | Крепость, передние скалы/лава, дорожка, конечный туман |
| `scripts/campaign/controller.gd` | Соединяет сигналы карты с существующими сервисами похода, сохранений и экранами |

Данные боёв остаются в `scripts/campaign/data/levels.json`, экономика — в `economy.json`. Визуальная карта не создаёт противников, не выдаёт наград и не меняет условия победы. Формат сохранений не изменён.

## Редактирование уровня

В массиве `levels` файла `level_map.json` каждая запись содержит:

```json
{
  "id": "level_05",
  "level_number": 5,
  "map_position": [1050, 184],
  "state": "auto",
  "chest_type": "gold",
  "repeat_chest_type": "bronze",
  "show_chest": true,
  "boss_placeholder_type": "question_mark_placeholder",
  "boss_icon_texture": "",
  "unlock_requirement": 4,
  "zone_id": "citadel",
  "markers": []
}
```

`id` и `level_number` должны быть уникальными. Порядок массива задаёт соединение маршрута. Координаты — в единицах дизайна карты, а не в пикселях экрана. X растёт слева направо; при текущей высоте `design_height: 260` Y основания должен быть в диапазоне 148–224. Компонент рисуется относительно основания, поэтому менять его вручную в сцене не нужно.

`auto` рассчитывает `current`, `completed`, `open` или `locked` по сохранению. Можно явно указать эти состояния либо `unavailable`. Ограничения настоящего прогресса имеют приоритет: несуществующий уровень всегда недоступен, а неоткрытый — заблокирован. Во время похода запускается только его продолжение. `unlock_requirement` хранит номер предыдущего уровня для подсказки; фактическим открытием по-прежнему управляет `CampaignRun` через `unlocked_level`.

Чтобы добавить **визуальную** позицию, скопируйте запись, задайте новый ID/номер/X/Y и `state: "unavailable"`. Конец карты автоматически переместится за последнюю позицию. Для настоящего нового уровня отдельно нужен боевой контент в `levels.json` и расширение существующих ограничений кампании в `levels.gd`, `run.gd` и валидаторе `save.gd`. Они намеренно сохраняют нынешний контракт пяти игровых уровней: смена картинки не должна позволять начать несуществующий бой. После добавления контента переключите запись карты на `auto`.

## Иконка босса

Сейчас все двадцать записей имеют одинаковую рамку с вопросом; изображения боссов не используются. Позже положите текстуру в `assets/` и задайте, например:

```json
"boss_icon_texture": "res://assets/campaign/bosses/guardian.png"
```

`BossSlot/Texture` покажет её с сохранением пропорций и скроет `BossSlot/Question`. Пустой или отсутствующий путь оставляет вопрос. `boss_placeholder_type` обозначает стандартный резервный вариант; никаких боссов из боевой сцены для превью не создаётся.

## Сундуки и награды

Три оформления: `bronze`, `gold`, `diamond`. Первый проход: 1–4 — бронза, 5 — золото; у будущих 10/20 — алмазный синий, 15 — золото, остальные — бронза. Недоступные сундуки затемнены. `show_chest: false` скрывает слот.

Это **оформления** существующих common/rare/epic сундуков, а не новые экономические типы. `repeat_chest_type: "bronze"` отражает действующее правило повторных прохождений. Вероятности и награды определяются только `CampaignEconomy`; изменение картинки в карте не меняет содержимое сундука. Меняя экономический тип, синхронно настройте его оформление. Процент награды и число побед доступны в подсказке узла; после прохождения число побед видно под платформой.

В `chest_skins` можно изменить `colour` или указать `texture: "res://assets/...png"`. Пустая текстура использует лёгкий векторный значок. Массив `markers` заполняет подготовленный контейнер небольшими текстовыми бейджами, например `["NEW"]`.

## Зоны, слои и скролл

Общая палитра — `theme`. Добавьте запись в `zones`, например `"ice": {"name": "Ледяная крепость", "theme": {"lava": "62bdd5", "banner": "425f9a"}}`, и задайте уровням `zone_id: "ice"`. Неуказанные цвета наследуются. Палитра фона выбирается по зоне в центре видимой части карты, платформа получает палитру своего узла.

В `parallax` сейчас строго задано:

```json
"parallax": {"middle": 1.0, "lower": 0.55, "upper": 0.25}
```

Средний слой — интерактивные уровни и путь, нижний — передние скалы/лава, верхний — дальняя крепость и небо. Смещение каждого равно `-scroll_offset × coefficient`. Для изменения скорости редактируйте только коэффициенты; средний оставляйте 1.0 для согласованной работы прокрутки.

`scroll` содержит сглаживание, порог свайпа, затухание инерции, предел скорости и долю ширины экрана для стрелки. `terminal` задаёт отступ, ширину конечной зоны и текст. `design_height`/`max_scale` управляют масштабом карты; HUD не масштабируется вместе с ней. Слишком маленькая высота окна уменьшит карту, поэтому целевая ориентация — горизонтальная, как у остальной игры.

Энергия пока показана как **«Энергия —»**: её стоимость, восстановление и источники не утверждены. Сохранение не получило новых полей, вход в бой ничего не расходует. Монеты и кристаллы берутся из существующего аккаунта.

## Нагрузка и проверки

Огромных фоновых текстур, частиц, физических тел и шейдерного размытия нет. Декорации строятся векторами только для видимых фрагментов и перерисовываются при движении/изменении размера. Только текущий узел и видимый конечный туман анимируются с перерисовкой до 24 раз в секунду. В покое обработка прокрутки отключена; 20 узлов — обычные UI-кнопки.

Проверки `campaign_map_data_test`, `campaign_map_navigation_test`, `campaign_map_integration_test` и `render_campaign_map_test` покрывают состояния, сундуки, отсутствие реальных иконок, параллакс, границы, свайп без случайного входа, изменение размера, переходы в существующие экраны и бой, продолжение похода и Home. Снимки и логи полного запуска находятся в `builds/campaign-work/map-final-validation/` (не входят в экспорт).
