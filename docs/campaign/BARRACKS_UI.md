# Художественная казарма

Казарма кампании заменена отдельным экраном кузницы. Свободные бои,
боевые характеристики, экономика, сохранения и контент кампании не менялись.
Контрольная точка перед работой: тег `barracks-art-baseline-20261022` (`8329343`).
Изменения находятся только в ветке `campaign-experiment`.

## Экран и компоненты

Вход остаётся прежним: карта кампании → «Казарма».
`scenes/campaign/barracks.tscn` содержит корневой экран;
компоненты находятся в `scripts/campaign/barracks/`:

| Файл | Назначение |
| --- | --- |
| `screen.gd` | Закреплённые верхняя/нижняя панели, выбор вкладок, локальная прокрутка, маршрутизация сигналов |
| `selector.gd` | Горизонтальная коллекция реальных героев, замки и выбранная карточка |
| `showcase.gd` | Крупная модель на платформе, описание, назначение основного героя/союзника |
| `preview.gd` | Изолированный SubViewport с настоящим `CampaignBall` и его оружием |
| `resource_bar.gd` | Настоящие монеты, XP и кристаллы, включая четверти ресурсов |
| `stats_panel.gd` | Шесть карточек и раскрывающиеся подробные параметры |
| `upgrade_panel.gd` / `upgrade_card.gd` | Динамический набор XP-улучшений и обратная связь |
| `training_panel.gd` | Отдельная тренировка способности за монеты |
| `weapon_panel.gd` | Настоящее оружие, семь ступеней, дробные карточки, мердж |
| `evolution_panel.gd` | Сбор дополнительных карточек и подготовка к будущей форме |
| `presentation.gd` | Адаптация существующих данных к подписям и карточкам, без мутаций аккаунта |
| `art.gd` / `ui.gd` | Общие текстуры, атласы, рамки и визуальные элементы |
| `forge.gdshader` | Слабое мерцание только горячих участков готового фона |

Вкладки и их корневые компоненты сохраняются при переключении. Выбор героя
не сбрасывается при прокачке или мердже. Содержимое скрытой вкладки обновляется
при её следующем открытии. При входе заполняется только активная вкладка.

## Источник данных и операции

- Значения карточек — `CampaignProgression.stats()` без временных бонусов забега.
- Следующее значение — тот же компилятор на временной копии аккаунта с рангом +1.
- Стоимость — `xp_cost()` / `coin_cost()`, без копирования формул в UI.
- Физическая модель — `CampaignProfiles.hero()` / `create_actor()`.
- Транзакции остались в контроллере: копия аккаунта → действующая операция
  progression → сохранение → публикация нового аккаунта только при успехе записи.
- Ошибка сохранения оставляет валюту и карточки в прежнем состоянии и выводит
  предупреждение. Кнопка повтора сохраняет актуальный аккаунт; отменённую покупку
  нужно запросить повторно.
- Обработчик экрана принимает не больше одной операции в кадре, защищая от
  повторного события нажатия. Стоимость всё равно заново проверяет progression.
- Активный поход блокирует постоянную прокачку, мердж и смену состава как прежде.
- Закрытого героя можно рассматривать и перейти в существующий магазин.
  Мердж его карточек остаётся доступен вне похода, как и до переработки.
- Слот союзника покупается в прежнем магазине. Назначение/снятие союзника
  доступно около модели; правила HP и поражения не менялись.

## Важные отличия от демонстрационных чисел концепта

Нет выдуманного общего уровня: вместо него показаны реальные ранги отдельных
улучшений. Не копируются цены, значения, броня, лица и будущие формы с концепта.
Дизайн настоящих игровых шаров и оружия сохранён.

У вампира вместо вращения показывается длительность укуса; монеты развивают
порог Охоты как долю базового HP, а не случайный шанс. У дубины тренируется шанс
дополнительного урона при ударе противника о стену; его защитный щит описан
отдельно. У ножевика вероятность указана за тик захвата. У катаны показывается
накопление кровотечений и рост их вероятности.

Оружие использует все семь действующих ступеней 50–110%, целочисленные
полукарточки и прежнее слияние 2 → 1. Галочка обозначает используемую ступень,
подсветка — выбранную для мерджа. Клыки вампира не меняют длину.

Шкалы рисуются только при существующем ограничении: тренировка способности,
вращение, восстановление, карточки и ступени. HP, урон и скорость не получают
вымышленного максимума.

Эволюции намеренно не активированы. Следующая форма обозначена вопросом;
показаны три дополнительные карточки и половинки. Нет выдуманных испытаний,
требований оружия, способностей и списания карт. «Как получить?» читает реальные
вероятности сундуков. Бесплатное получение кристаллов/платежи не добавлялись.

## Графика и производительность

Самостоятельно созданы четыре PNG через встроенный imagegen:
`assets/campaign/barracks/{forge,pedestal,frames,icons}.png`.
Полный набор промптов и режим сохранён в `prompts.json` рядом с ними.
Фон — 1672×941; платформа — 1774×887; рамки — 1536×1024;
иконки — 1448×1086. Исходники не обрезаны и не перерисованы кодом;
рамки/иконки читаются через AtlasTexture. Валютные монета и кристалл
переиспользуются из атласа карты.

Исходные PNG суммарно занимают 7 776 306 байт (около 7,42 MiB).
Импорт ограничивает платформу и атласы до 1024 пикселей, фон — до 2048;
используются mipmaps. Размер исходника не равен расходу видеопамяти.

Предпросмотры имеют отдельный World2D, замороженные тела, нулевые collision
layer/mask и полностью отключённые process/physics callbacks всего дерева.
Они рисуются `UPDATE_ONCE` только после изменения профиля. Миниатюры используют
128–240 пикселей, большие модели — 480×480, без 3D и постоянных боевых симуляций.
В компактной мобильной демонстрации используется 720×300 и горизонтальная
поза оружия, чтобы модель лучше заполняла широкий невысокий участок экрана.
Экран не имеет собственного покадрового обновления. Фоновый шейдер использует
один sample текстуры, без частиц, размытия и дополнительных проходов.

Основной приоритет — горизонтальные экраны. Верхняя панель, коллекция и нижние
вкладки закреплены. Прокручивается только содержимое правой панели, а длинный
список героев/ступеней — по горизонтали. На небольшом телефоне полное описание
героя доступно кнопкой ⓘ, на большом экране оно дополнительно видно над моделью.
Учитывается безопасная область мобильного окна. APK в рамках задачи не собирался.
