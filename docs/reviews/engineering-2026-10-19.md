# Техническое ревью BallArena

Работа начата 17 октября и завершена 19 октября 2026 года. Исходная версия: `cb69eef`. Все изменения выполнены в согласованной основной папке и ветке `main`. Экспериментальный worktree и его ветка не изменялись.

Задача: исправить инженерные дефекты и обеспечить проверяемую разработку, сохранив параметры персонажей, механику, физику обычного боя и визуальный дизайн. Это отчёт о проверенных исправлениях и границах проверки, а не утверждение об отсутствии любых будущих ошибок.

## Исправленные проблемы

| Область | Найденный дефект / риск | Исправление |
|---|---|---|
| Регистрация боя | Повторная регистрация, устаревшие подписки и принадлежность другому директору | Идемпотентная регистрация, явное снятие регистрации и подписок, удаление ожидающих контактов ушедшего компонента |
| Поздние компоненты | Способность, добавленная после старта, могла не получить seed матча | Инициализация через единый путь регистрации, без изменения RNG существующих боёв |
| Зависимости директора | Чтение частных полей конкретного меча | Общий контракт `weapon_sweep_motion()` в базовой способности |
| Ресурсы | Вложенные изменяемые параметры могли разделяться шаблоном и экземплярами | Независимые глубокие копии контейнеров профиля/способности |
| Входные данные | Неверные типы, неизвестные поля, конфликт имён узлов, повторные способности | Проверка до частичного применения; общая проверка состава `BattleRoster` |
| Запуск арены | Неверный итоговый override мог быть отклонён уже после создания матча, оставляя сценовые defaults | Полная предварительная проверка используемых итоговых профилей; отклонённая арена не создаёт стены/директор и не двигает тела |
| Смена профиля | Изменение тела/HP до завершения старой способности могло оставить удерживаемую цель | Сначала деактивация старых способностей, затем применение профиля |
| Владение статусами | Удаление источника оставляло заморозку или защиту; один источник мог мешать очистке другого | Отдельный tracker со слабыми ссылками и очисткой по источнику; поддержка отсоединения/возврата владельца и источника |
| Прерывание укуса | Сброс, смена профиля, освобождение жертвы или выход способности могли оставить активный захват | Единое безопасное завершение, проверка освобождённых объектов, освобождение обеих сторон |
| Граничные состояния HP | Повторный урон уже мёртвому телу мог вернуть некорректную величину | Идемпотентный нулевой результат; нулевая длительность паралича не замораживает тело |
| Метрики | Повторное подключение и разделяемые словари результата могли искажать снимки | Очистка состояния при подключении, безопасное отключение, независимый результат `finish()` |
| GPU-распад | Освобождение персонажа во время `await frame_post_draw` могло оставить busy-флаг/временный viewport | Повторная проверка после await, отменяемая очередь слабых ссылок, освобождение временных ресурсов на всех путях |
| Фрагменты | Освобождённые тела/способности и изменение числа сегментов ломали прокси столкновений | Проверка действительности ссылок, обновление прокси при изменении геометрии, идемпотентные подписки |
| Эффекты | Устаревшие ссылки на участников высасывания, несогласованные бюджеты MultiMesh | Удаление завершённых связей; буфер согласуется с изменённым лимитом без изменения стандартных лимитов |
| Геометрия | Тела и иконки зависели от частной геометрии службы крови | Нейтральный `scripts/effects/mesh_geometry.gd`, прежние публичные обёртки сохранены |
| Ненужная работа | Повторные вычисления метрик текста, пустых массивов кровотечения, перерисовок ветра/глаз | Кэширование стабильных данных и обновление по изменению состояния |
| Мёртвый код | Неиспользуемый `vampire_fur.gd` ссылался на уже отсутствующий метод | Удалён только подтверждённо неиспользуемый renderer; утверждённый PNG и действующая графика сохранены |
| UI-зависимости | Экраны загружали старый экран выбора ради словаря, дублировали стили и портреты | Общие `character_text`, `menu_styles`, `portrait_preview` в `scripts/ui/`; совместимые обёртки старого экрана |
| Портреты | Предпросмотры сохраняли ненужные боевые обработчики и повторно записывали буфер/layout | Статичная безопасная подготовка без боевого процесса, обновление буфера при изменении размера/трансформации |
| Навигация | Прежние HUD/сцены и callbacks результата могли пережить переход к новому бою | Явное отключение сигналов и удаление старого боя/HUD, проверка актуальности callback |
| HUD | Массовые попадания вызывали несколько одинаковых групповых пересборок за кадр | Объединение групповых обновлений; публичное синхронное обновление и дуэльный путь сохранены |
| Проверки | Нулевой exit, старый PASS или остановка по лимиту кадров могли выглядеть успехом | Версионируемый runner проверяет завершённый PASS, exit, ошибки и утечки; очищает лог и ограничивает время процесса |
| Графические тесты | Проверка GPU-захвата при смерти ошибочно попадала в headless | Отдельная графическая серия для всех пяти вооружённых героев и render-тестов |
| CLI симуляций | Неполные аргументы, неверный JSON/тип, нулевые счётчики, пустой прогон и ошибки записи | Общее небольшое средство проверки/I/O только для offline CLI; явный ненулевой exit вместо ложного PASS |
| Агрегатор | Повторные, отсутствующие, чужие испытания или несовместимые отчёты могли исказить статистику | Проверка идентичности seed/candidate/swap и полноты; проверка версий/параметров/hash/Hz, сохранение реальной Hz источника |
| Инструменты и процесс | Проверки зависели от локальных путей/помощников, отсутствовал общий автоматический барьер | Python runner без сторонних пакетов, CI с закреплёнными зависимостями, `.editorconfig`, binary attributes и правила разработки |
| Экспорт | Ошибка импорта Godot не всегда останавливала скрипт сборки | Отдельная проверка exit и текущего журнала импорта/экспорта; выбор Godot через аргумент, env или PATH |

## Структура и совместимость

- Общие контракты и проверка состава находятся в `scripts/combat/`.
- Общая инфраструктура статусов — в `scripts/actor/`, UI-помощники — в `scripts/ui/`, геометрия — в `scripts/effects/`.
- Ручные диагностические preview-скрипты перенесены в `tests/manual/` вместе с UID; их не удаляли.
- Проверки инструментов — `tests/tooling/`, offline CLI helper — `tests/support/`.
- Логи, картинки и результаты остаются в игнорируемом `builds/`. Ключи подписи, Python cache и `.env` исключены из Git.
- Сцены, существующие публичные пути и совместимые интерфейсы сохранены. Массового переименования всех скриптов и полной замены архитектуры не проводилось: это увеличило бы риск скрытого изменения игры без самостоятельной пользы.

`CONTRIBUTING.md` описывает ответственность каталогов, жизненный цикл, безопасную работу после await, изоляцию параметров/RNG, проверки, логические коммиты и запуск экспорта только по просьбе владельца. Памятка проекта актуализирована в существующих разделах.

## Проверка сохранения игры

Все 19 исходных файлов в `characters/`, `assets/`, `shaders/` совпали с исходной версией по SHA-256. Значения урона, HP, скоростей, весов, времени захвата, кулдаунов и шансов не подбирались и не менялись. Git также подтвердил отсутствие изменений сцен и настроек проекта.

До и после рефакторинга записан одинаковый диагностический прогон настоящей физики Godot: все 15 различных пар из шести героев, воспроизводимые начальные условия, по 960 физических шагов. Сравнивались HP, положения, скорости, неподвижность и неуязвимость каждые 30 шагов. Все записи совпали точно, включая финальный повтор после последних исправлений. Это проверяет обычную последовательность боя на выбранных сценариях; не доказывает эквивалентность всех возможных матчей. Исправленные некорректные входы/удаления намеренно ведут себя безопаснее исходной версии.

## Выполненные проверки

Среда: Windows, локальный Godot 4.7.2 Standard, Compatibility renderer.

| Проверка | Результат |
|---|---|
| Импорт проекта | PASS |
| Полная headless-серия после финальных исправлений | 40/40 PASS |
| Графические тесты, включая GPU-распад пяти вооружённых героев | 15/15 PASS |
| Проверки самого Python runner | 7/7 PASS |
| CLI симуляций/слияния | PASS, включая реальные дочерние процессы с ошибочными входами и корректный короткий прогон |
| Статусы/удаления/переподключение/смена профиля | PASS, отдельные регрессионные сценарии |
| Синтаксический разбор PowerShell exporter | Без ошибок; экспорт APK не запускался |

Runner: `python tools/run_tests.py --godot <путь> --suite headless --jobs 2`; графика — `--suite graphics`; инструмент — `python -m unittest discover -s tests/tooling -v`. Локальные журналы находятся в `builds/qa-final`, `builds/qa-graphics`; эти результаты не включаются в исходники. GitHub Actions повторяет headless на Linux при публикации main/PR и сохраняет журналы как artifact. Движок сверяется с официальной SHA-512; версии Actions закреплены по commit SHA.

## Границы результата

Проверка на Android и новый замер FPS на OnePlus в эту работу не входят. APK не пересобирался. Ускорения здесь относятся к конкретным устранённым повторным вычислениям/обновлениям и управлению ресурсами; новый процент прироста FPS не заявляется.

`ball.gd` и семейство оружия остаются крупными координирующими компонентами. Из них вынесены подтверждённо повторяемые ответственности, но дальнейшее дробление стоит делать по конкретной задаче и тестам, а не по числу строк. Конфигурационный валидатор предназначен для действующих профилей, а не для исполнения произвольных пользовательских скриптов или защиты от недоверенных модов.

Исторические документы и отчёты баланса сохраняются как история. Они не заменяют текущие `.tres` и не являются новой статистикой баланса после ревью. Ревью, интеграционные тесты и CI снижают риск, но не гарантируют отсутствие дефектов на всех устройствах и будущих комбинациях героев.
